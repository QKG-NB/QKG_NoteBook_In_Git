#### 一、`TRIGGER` 指令的两种核心写法

| 触发方式         | 指令模板                                                      | 触发基准                              | 适用场景                          |
| ------------ | --------------------------------------------------------- | --------------------------------- | ----------------------------- |
| **基于距离终点距离** | `TRIGGER WHEN DISTANCE = 1 DELAY = 0 DO 子程序() PRIO = 5`   | 基于**运动终点**（精确点）或**逼近弧中点**（C_DIS点） | 需要在到达目标点**之前/之时/之后**的某个位置触发动作 |
| **基于路径长度**   | `TRIGGER WHEN PATH = -20.0 DELAY = -10 DO 子程序() PRIO = 5` | 基于**实际运动路径长度**（毫米），沿路径倒推          | 需要精确的**空间距离触发**，与速度无关，时序更稳定   |

---

#### 二、关键参数详解

##### 1. `DISTANCE`（仅用于 `WHEN DISTANCE`）

- **`DISTANCE = 0`**：在**运动起点**触发
    
- **`DISTANCE = 1`**：在**运动终点**触发
    
    - 若目标点不带 `C_DIS`（精确点）：在**精确到达目标点时**触发
        
    - 若目标点带 `C_DIS`（轨迹逼近）：在**逼近弧线的中点**触发
        
- **作用**：定义一个**参考位置点**，再配合 `DELAY` 做时间偏移
    

##### 2. `PATH`（仅用于 `WHEN PATH`）

- **`PATH = 负值`**：在**到达当前运动段终点前** N 毫米处触发（如 `-20.0` 表示前20mm）
    
- **`PATH = 正值`**：在**离开当前运动段起点后** N 毫米处触发
    
- **单位**：**毫米（mm）**
    
- **优势**：不受机器人速度变化影响，基于固定空间距离触发，时序更精准
    
- **限制**：仅适用于 `LIN` 或 `CIRC` 等连续轨迹运动（**不能用于 `PTP`**）
    

##### 3. `DELAY`（两种方式通用）

- **单位**：**毫秒（ms）**
    
- **`DELAY = 0`**：在触发点**准时**执行
    
- **`DELAY = 正数`**：在触发点**之后**延迟 N 毫秒执行（如 `DELAY = 1000` 表示延时1秒）
    
- **`DELAY = 负数`**：在触发点**之前**提前 N 毫秒执行（如 `DELAY = -10` 表示提前10ms）
    
- **⚠️ 硬性限制**：延迟/提前时间**不能超过当前运动段总时间的 50%**，否则系统会强制在 50% 时间点触发
    

##### 4. `PRIO`（优先级）

- 当 `DO` 后面跟的是**子程序调用**时，**必须指定优先级**
    
- 可用范围：**1, 2, 4-39, 81-128**（避开系统保留的 3 和 40-80）
    
- 用于决定该触发任务的执行优先级

#### 三、🎯 核心概念：“切换区域”（生命周期 / 有效窗口）

##### 1. 切换区域是什么？

- 指 **`TRIGGER` 指令从生效到过期作废** 的那一段连续轨迹
    
- **起点**：`TRIGGER` 指令后面的**第一条运动指令**开始
    
- **终点**：程序中**下一个不带 `C_DIS` 的精确停止点**（即机器人会精确停下的点）
    

##### 2. 为什么需要这个区域？

- **往前借路径**：当 `PATH` 为负值且当前运动段长度不够时，系统允许沿着切换区域**往前回溯**，从之前的路段“借”距离来凑足触发位置
    
- **往后借时间**：当 `DELAY` 为正值且需要在到达后延时执行时，系统允许触发任务在切换区域内**继续存活**，即使机器人已经滑过了多个 `C_DIS` 点，延时结束后依然能执行动作
    

##### 3. 示例代码拆解

krl

LIN P_2 C_DIS
TRIGGER WHEN PATH = -20.0 DELAY = -10 DO $OUT[2] = TRUE
LIN P_3 C_DIS
LIN P_4 C_DIS
LIN P_5                 ; 精确停止点（不带 C_DIS）

- **`TRIGGER` 的基准运动**：紧跟在后面的 `LIN P_3 C_DIS`（不是 `P_2`！）
    
- **触发点计算**：在 `P_3` 这段路径上，距离 `P_3` 终点前 20mm 处触发，再提前 10ms 执行
    
- **切换区域（生命周期）**：从 `LIN P_3` 开始，到 **`P_5`** 结束（因为 `P_5` 是第一个不带 `C_DIS` 的精确停止点）
    
- **为什么是 `P_5` 不是 `P_3`？**：因为 `P_3` 和 `P_4` 都带了 `C_DIS`，机器人在这些点不会停，所以 `TRIGGER` 的有效监控一直延续到 `P_5` 才结束
    

##### 4. 切换区域对触发的影响

|场景|触发点能否找到？|
|---|---|
|P2→P3 路径长度 ≥ 20mm|✅ 直接在 P3 段内找到触发点，区域长度不影响|
|P2→P3 路径长度 < 20mm|✅ 系统沿切换区域**往前回溯**，借 P2→P3 之前的路径凑足 20mm，触发点落在更早的位置|
|若 P3 是精确停止点（无 C_DIS）|❌ 切换区域到 P3 结束，无法往前借路，若路径短于 20mm，触发点失效或强制落在起点|

#### 四、❌ 常见错误与注意事项

|错误|后果|正确做法|
|---|---|---|
|`TRIGGER` 放错位置（如写在运动后面）|触发不生效，或作用于错误的运动指令|`TRIGGER` 必须紧挨着放在**目标运动指令之前**|
|`PATH` 用于 `PTP` 运动|编译报错|`PATH` 只能用于 `LIN` 或 `CIRC`|
|`DELAY` 值超过运动总时间的 50%|实际触发时间被截断，与设定不符|减小 `DELAY` 值，或加长运动路径|
|忘记指定 `PRIO`（子程序调用时）|编译报错|调用子程序时**必须写 `PRIO = N`**|
|子程序内包含 `WAIT` 或运动指令|可能打断运动预进，触发时机错乱|子程序内只做赋值、输出等轻量操作|

---

#### 五、✅ 总结

|对比项|`WHEN DISTANCE`|`WHEN PATH`|
|---|---|---|
|**触发基准**|位置点（终点或弧中点）|路径长度（毫米）|
|**受速度影响**|是（时间延迟受速度影响）|否（固定距离，不受速度影响）|
|**适用运动**|`PTP` / `LIN` / `CIRC` 均可|**仅** `LIN` / `CIRC`|
|**核心用途**|位置点触发 + 时间偏移|高精度空间距离触发|

**🎯 一句话核心**：`TRIGGER` 的“切换区域”本质上是给触发任务提供了一个**灵活的生存窗口**——在这个窗口内，系统可以**往前借路**（解决 `PATH` 负值距离不够）和**往后延时**（解决 `DELAY` 正值等待问题），确保触发动作在连续运动中依然能精准执行。
